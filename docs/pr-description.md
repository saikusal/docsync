## Summary
Adds **docsync**, a Node.js/TypeScript CLI that keeps a repository's README in sync with its code, as specified in user story
[DOCS-101](../user-story/DOCS-101-docs-sync.md). It extracts facts from the code (env vars, Express routes, npm scripts, dependencies,
license, folder layout, GitHub metadata) and rewrites only the README sections between `docsync` markers; `docsync check` fails CI
when a code change makes the docs stale. The whole change was delivered through the agentic SDLC pipeline in `.claude/`, and every
phase left an approved artifact in `docs/`.

## Known Limitations
- **Not Found by design:** the GitHub-only overview fields (default branch, topics, latest release) show `Not Found` without `GITHUB_TOKEN`; env vars that appear only in `.env.example` show `Not Found` for "Required" and "Used in"; non-static route paths show `Not Found (dynamic)`; unknown folders show `Not Found` as their purpose.
- **Out of scope (v1):** frameworks other than Express; languages other than JS/TS; monorepos (root `package.json` only); files other than the README; writing to GitHub (auto-commit, auto-PR, PR comments: DOCS-102); middleware/auth per route.
- **Static-analysis limits:** routes registered in loops or helpers, `process.env[computed]` and aliased `process.env` aren't detected; re-exports are followed one hop.
- **Deferred or waived findings:** CR-8 (one low `esbuild` advisory, dev-only), CR-9 (real-TTY prompt untested), DD-17 (no macOS in the CI matrix).
- Remote mode needs about one API request per source file; very large repositories must be checked out locally.
